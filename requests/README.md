# Development requests

Substantial changes are tracked in their own request folders.

## Workflow

1. Read the repository instructions, relevant requests, and relevant knowledge.
2. Create or update `request.md`, `implementation-plan.md`, `testing.md`, and `notes.md`.
3. Present the implementation plan and wait for Oliver's explicit approval.
4. Implement only the approved scope on a focused branch.
5. Run automated checks, production build, and relevant manual verification.
6. Review the diff and document actual outcomes in the request folder.
7. Update reusable knowledge and deployment notes.
8. Merge only after verification and explicit review.

Do not implement while a request is awaiting approval. Do not claim tests, deployment, or manual checks that were not actually performed.
